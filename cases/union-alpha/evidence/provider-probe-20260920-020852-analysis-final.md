**结构（关键）**：三家偏离上游与多数值的差在每个探针上**恒定**——**Phala +68**、**Venice +37**、**Alibaba / Novita −4**，四探针零偏差。即：**上游之间的差异是"同一 tokenizer + 每上游一个固定包裹偏移"**，不是"不同 tokenizer"（后者会给出随内容浮动的差）。

## 四、方法学含义

1. **参照臂读数 = f(model id, 上游 provider, 内容)**，且**公开权重模型的"同一 model id"下藏着多套计数口径**。任何 Δ 归因在读参照臂时必须：① 记录 `provider`；② 校验同一探针的参照臂读数是否唯一；③ 不唯一则按 provider 分层，而不是按"时间序列"处理。
2. **定值层混淆（本批最重要的一条）**：Δ 恒定只能推出"同 tokenizer + 一个固定差"，**不能**推出这个固定差来自哪一层。本案例里**同一个 +/− 常数结构在三层上都出现过**：部署包裹 **+7**（9/17→9/18 平移）、家族间隔 **51**、上游包裹 **−4 / +37 / +68**。因此Δ 判据必须与控制层绑定（同一端点 × 同一上游 × 同一窗口），否则恒定性会被误记到错误的层上。
3. **闭合性检验的反例风险**：本案例的家族闭合用了两个**闭源单上游**参照臂（qwen3.8-max / qwen3.7-max，本批 30/30 落在 Alibaba），但第三臂 `qwen3.8-27b` 是**开放权重多上游**——**若平台当时把它路由到 Phala，第三臂的算术会一次性偏 +68 而看起来像"家族闭合失败"**。事后复核：9/18 与 9/20 的第三臂读数分别落在 Reka（68）与 Phala（136），而 9/18 那次恰好满足 −46 的预测。因此**该预测的成立部分依赖路由运气**，这一点必须写进论文的诚实局限。
4. **未关闭项**：`unbiased/pareto` 的 90 次读数 provider 恒为 `Unbiased`（单上游端点），故本批**不改变**"引擎 vs 上报口径"（P1.2）的开放状态；本批只证明**该字段在存在上游差异时确实会变**（q27b 上它变了），因而 Pareto 侧的不变是"该端点只有一个被列出的上游"，而不是"字段不敏感"。
5. **机制不作推测**：为什么各家上游的固定偏移不同（系统提示、模板、部署差异），无证据区分，不写。
